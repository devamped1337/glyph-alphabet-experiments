# Grok: preference on E1d fresh-test F2 fix (relayed by Stefan, 2026-10-19)

Option A.

Keep the credit range at 2–9 and expand with six new role pairs. The point of the fresh set is to test unseen rules, not to change arithmetic difficulty at the same time. Two-digit numbers (Option B) add a new cognitive load; if accuracy drops you will not be able to tell whether the ID path worsened or the task just got harder. Option A isolates the variable that matters.

Risks that still apply:
- New role pairs must be generated from the same template and checked for uniqueness against all E1b/E1c material (and any dev seeds). Dated, disclosed amendment required either way.
- Throwaway dev seeds are mandatory before freeze to confirm the new rules parse, produce gold labels, and do not leak.
- Coverage and wrong-ID behaviour on the new pairs may still differ; report it separately, but that is not a reason to avoid A.
- 419 is still a finite pool. Burning a large fraction on dev/calibration recreates the same shortage next round.

Prefer A. Freeze the generation method and the exclusion list in the amendment, then run the throwaway seeds before anything else.
